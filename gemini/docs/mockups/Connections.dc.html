Connections

Each tool with your own account. Tokens live in the macOS keychain. Team defaults come from .gemini/geminicode-tools.json.

This repository's .gemini/settings.json runs Jira and GitLab as MCP servers of the CLI

Agents see two sets of Jira and GitLab tools, and the servers' tokens come from your shell environment, which the agent's shell tool can read. GeminiCode can run the same two containers itself: tokens move to the keychain, the images are pinned, the agent sees one server with 17 tools instead of two with 106, and Home can use the same tools.

Nothing changes until you choose. The settings file is edited in place and can be reverted with git.

What every agent gets

One server, geminicode-tools, listing only connected tools: 17 tools, about 1,600 tokens of schemas per request. Reads run without a card; comments and replies ask; moves, time logs, new merge requests and merges ask every time.

What the tokens can do

Jira: this token is unscoped; a scoped token with read and write on work items is offered when the site allows it. GitLab: api is the only scope that can open merge requests; approval rules on the server remain the floor.

Where things live

Tokens: macOS keychain. Server addresses and the Jira email: GeminiCode's global state. Team defaults: the repository. Nothing leaves this Mac except the calls themselves, over your VPN.
