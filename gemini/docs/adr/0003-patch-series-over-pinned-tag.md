# ADR 0003: Upstream edits are a patch series over a pinned release tag

**Status:** accepted on 2026-10-18 and in place: `gemini/upstream.json`, `gemini/patches/`, `gemini/scripts/upstream-series.sh` and `gemini-upstream.yml` carry it out. The branch protection it calls for is not set up yet ([ROADMAP.md](../ROADMAP.md#repository-settings)).

## Context

The fork merges upstream release tags three-way. The set of upstream files it edits is small: about 40 code and config files, plus icons. Without a written series, each move would be a manual checklist built from the `GEMINI-FORK` markers, which JSON files and icons cannot carry, and nothing would move the base or the Gemini CLI pin.

## Decision

- `gemini/upstream.json` pins the upstream release tag.
- Every edit to a file outside the fork-owned paths is kept as a patch in `gemini/patches/`, regenerated by `upstream-series.sh regenerate` (`git diff --binary` against the tag). A CI check (`upstream-series.sh check`) fails when the series is stale.
- `gemini-upstream.yml` takes the newest `1.N.x` release tag above the pin and opens one PR. On the way it applies the series, copies the fork-only paths, moves the pin, regenerates the series and bumps `bundledCli` to the newest `@google/gemini-cli` with its integrity. Gemini CI then runs the full compile, hygiene, the extension tests and the real-CLI tests against that exact CLI version on the PR.
- Branch protection requires the Gemini CI jobs; nothing merges with one red.
- History is not rewritten: existing clones keep working.
- Upstream's GitHub automation (its workflows and Dependabot config) is not part of the fork, because the repository never goes back upstream. `apply` and `prune` remove it, and `check` fails while any of it is there.

## Consequences

- A conflict stops in CI with the patch name, not in a developer's merge.
- Reducing the number of patches becomes a visible metric.

## Evidence

In the move from 1.141.0 to 1.142.0, 72 of the 74 patches applied cleanly. Two needed a hand merge, in files the fork edits at one point each, and the series stayed at 74 patches. CI's `Patch series matches HEAD` step checks the series on every pull request.
